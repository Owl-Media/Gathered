# Events

A platform-wide list of every event, for a sense of scale and activity.

> Reply totals across the platform. Guest details are not shown.

## The table

| Column | What it shows |
| --- | --- |
| **Event** | The event name |
| **Organiser** | The organiser's name, with a **Disabled** badge if their account is off |
| **Date** | The event date |
| **Invited** | Guests currently on the list |
| **Accepted** | Guests who are coming |
| **Declined** | Guests who are not |
| **Waiting** | Guests who have not replied |

That is the entire page. Counts and nothing else.

On a narrow screen the table scrolls sideways rather than compressing into unreadable columns.

## What is not here

- **No guest names.** Not one, anywhere.
- **No menu selections, dietary requirements or messages.**
- **No links into the organiser's event management pages.** There is no route from this table into an event; the pages behind it check ownership, and an administrator does not own it.
- **No public or invitation links.**
- **No payment data.**
- **No editing of anything.**

## What it is useful for

Answering operational questions without reading anybody's event: how many events exist, whether an installation is being used, whether an organiser who reported a problem has any guests yet, whether replies are coming in at all.

For anything beyond that, the organiser has to look themselves. That is the intended boundary — see [Privacy](/privacy/index).
